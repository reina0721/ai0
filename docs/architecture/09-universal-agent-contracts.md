# 通用 Agent 的扩展边界与验证方案

## 维护者要保住的选择

第一次遇到一种新能力时，希望作者可以给它命名、实现它、复用它，并在已有接点上声明多个用途。宿主为每项用途选择提供方、受众、权限和生命周期。发起方选择本次入口，目标核裁决这次结果能证明什么。删除其中一个入口，其他获准入口应能独立工作。如果现有契约会把真实发生的事情记错，才需要修改共同语义。

“五核同等级”指每个核对自己的事实有最终裁决权。最小单步 Agent 只需接收输入、组装请求、调用模型并结算。它不需要加载五个业务组件。五核九包是当前部署约束，包数由后续 ADR 和独立消费者证据决定。

## 对两个设计提议的判断

- 采纳 Gemini 的空装配、动态状态轴、具名回复契约、载体与切面正交，以及检查真实出口。对照 dsh，同一个 Agent 句柄可以由不同 driver 实现，生产配置与最小 SDK 配置可以分别组装。这为“保持接口，替换提供方”的实验提供了参照。[dsh 核心与驱动](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/core.zh.md)
- 将“自动跨核注入”限定为按声明产生候选绑定。能列出 MCP 资源、获准订阅资源、收到更新，以及将更新作为观察接纳，是四件事。Markdown 自由文本也不能自行获得工具执行权或长期状态写权。[MCP 资源规范](https://modelcontextprotocol.io/specification/2025-11-25/server/resources)
- 收紧 GPT 方案里容易被误读的“通用”。独立作者可在扩展命名空间定义平台未知的服务。只有消费方必须共同识别新状态、授权边界或失败结果时，才扩大核心契约。dsh 删除了只有一个真实产品用例的模式注册表，这同样适用于 ai0 的预设切面清单。[dsh 的模式注册表删减记录](https://github.com/deepseek-ai/deepseek-harness/blob/f4185122/.agents/notes/implemented/simplification/2026-07-22-plan-specific-collaboration-state.md)
- 净空历史默认与兼容层（Clean-Slate V1 Iron Law）：移除全部历史种子摘要表、`legacy_unknown`、`D2_HOMEOSTASIS_AFFECT`、`agentToolDefinitionFacet` 等过渡兼容分叉，统一使用单版本 `agent.tool_provider@1` 与独立命名的 `perception.source@1`，并将多态载体投影（`mountCarrierProjections`）下沉至 `@ai0/sdk`。

## 四组契约的改动半径

| 作者与变化 | 定义、消费和依赖 | 新增能力需要改哪里 | 升级公共契约的反例 |
|---|---|---|---|
| 新模型供应方 | 协议定义标准消息、能力声明与流事件。适配器经 SDK 实现，运行驱动消费，凭据归宿主。 | 添加适配器和提供方绑定，验证取消、工具请求和结束。 | 已发布增量可以被模型撤回，历史与展示必须共同识别撤回。 |
| 新工具作者 | 作者给出输入 schema、规范结果、执行与模型结果投影。请求组装与执行共享定义，进程内流程可单独消费规范结果。 | 工具入口绑定已有服务，宿主授权后才向模型公布。 | 操作可以挂起且跨重启恢复，调用者必须共同区分“等待”“失败”“已执行”。 |
| 新上下文资料源 | 资料源提供内容、来源、版本和适用范围。宿主授予指令权威，组装器裁决本步骤的可见顺序和预算。 | 增加贡献者或已有接点的桥接。每次模型步骤保留组装清单，每次实际出站另记指纹。 | 新的覆盖或权威语义会改变多个来源的裁决顺序，而且现有语义无法表达。 |
| 第三方服务和插件作者 | 扩展拥有业务契约，组合层拥有作用域、版本、绑定、冲突和撤销。消费者依赖契约。 | 发布第三方定义、实现和需要的切面。提供方失效后，依赖它的入口应退出或等待。 | 多提供方原子切换成为多个消费者共同依赖的可观察保证。 |

## 三个能力域各自保证什么

| 域 | 核裁决的事实 | 交给扩展的决定 | 关闭后的判据 |
|---|---|---|---|
| 感知 | 来源、受众、修订和有效性 | 解码、筛选、去重、显著性、置信度修正和鲜度规则 | 未声明覆盖范围的来源无法制造持续有效的观察 |
| 认知 | 获准状态提案的版本、归属、冲突和提交 | 连续状态轴、更新函数、检索与规划、上下文贡献、回复解码与增量映射 | 零状态扩展时 D2 为空；禁用结构化输出后话轮保留纯文本 |
| 表达 | 可达端点、交付约束、打断与回执 | 渠道呈现、视线、语气、媒体时间轴和降级策略 | 无装饰器时文本仍可交付；无端点时无法凭空产生送达回执 |

当前 daemon 黑板仍对产品配置中的共享域分别授予读写权限。第三方可以自有私有状态、声明连续状态轴或发表版本化服务；跨包共享全新的持久黑板域还需要证明并实现命名、授权、恢复和遗忘的一致约定。只扩大域名枚举无法满足这些保证。

宿主在 Studio 配置中列出交互话轮可调用的查询工具（`readOnlyTools`，且 W1 强制校验 `capabilityRisk === "read_only_safe"` 与认知污点门控），并通过 `maxInteractiveSteps` 确定每轮最多的模型步骤。写改与命令执行等副作用能力（如多态插件 `builtin.workspace-tools` 提供的 `write_file / edit_file / run_command`）绝不硬编码进感知/认知/表达核心源码：在 `@ai0/agent-runtime` 的 `"direct_inline"` 编码任务拓扑中经策略与同轮污点熔断校验后直接内联闭环；在 `"dual_speed_w1_w2"` 具身伴侣拓扑中则路由至 W2 多步工具环，实时推进 `D4` 本体感觉状态供表达层感知，并响应 `AbortSignal` 打断取消。被动工作区文件变更监听（`workspace.fs_watch`）通过 `perception.source@1` 进入感知过滤管线，与内环主动求知工具 `workspace.read_file` 正交互补。标准 `SKILL.md` 在未显式声明 `projections` 时默认按需投影为 `agent.skill_manual@1`。

## 用字幕校勘推翻错误设计

第三方服务给出区间 1000–3000 ms 与 2500–4000 ms 的交集 2500–3000 ms。模型工具和直接调用都应取得 500 ms。服务作者定义算法，工具作者定义对模型的投影，编辑事件与显示端分别提供感知和表达入口。人工复核可以接受这次重叠，机器查询不应顺带写入人工意见。

1. 删除模型，流程仍可调用服务。删除高亮端点，模型仍可查交集。禁用工具，编辑事件仍可触发观察。
2. 换成 MCP 提供方，保持规范结果。Skill 可以说明校勘步骤并声明接点，只授予资源读取时无法执行编辑。
3. 在公布工具后撤权或替换实现。本步骤的旧授权和代次必须失效。记录失败原因，避免请求悄悄转到新实现。
4. 收到结果后断连。系统可以记录“服务算出 500 ms”，展示仍取决于可核实的端点回执。工作流观察者不得触发第二次执行。

## 冻结与撤回顺序

| 阶段 | 验证材料 | 允许冻结的决定 |
|---|---|---|
| 0 归属审计 | 对同一话轮标记输入、模型可见内容、持久事实和交付结果的所有者。列出旧种子与用户修改。 | 确定每项事实唯一负责方 |
| 1 最小运行 | 无角色、工具、长期记忆的单步请求，更换驱动和提供方。 | 运行、取消、结果与失败约定 |
| 2 作者替换 | 模型、工具、资料源、第三方服务逐组替换，加入冲突、撤权、卸载实验。 | 四组已被消费者使用的契约 |
| 3 多入口消融 | 字幕案例逐项拆除感知、工具、复核和展示；比较直接调用与模型投影。 | 经激活和卸载都验证的切面 |
| 4 生产对账 | 在实际 daemon 和受控 HTTP 传输比较预览、步骤清单和出站字段。启用再停用伴侣契约，检查 D2、输出约束、台词与呈现。 | 生产装配、可诊断的来源与回执 |
| 5 物理边界 | 重跑 Stage 0–7、包依赖门禁和产品回归。重新审视单消费者抽象。 | 保留、合并或按新 ADR 拆包 |

预览需要相同输入、受众、会话快照与绑定代次才可与一次实发比较。预算和来源属于逻辑清单，供应商字段改写属于出站记录。原生插件自带私有传输时，宿主只能证实经过受控传输的内容。空出站记录本身不能证明外部请求已经发送。

标准模型适配器和运行驱动按增量处理文本。现有 WebChat 在 W1 完成结果提交后分块交付正文。若以后要求把供应商每个文本增量立即呈现，需要为工具轮中的中间文本、取消和已展示前缀补充交付约定。
