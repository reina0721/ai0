## 一、感知层（上行输入）：可信溯源、流式话轮与隐私前移

外部躯壳插件采集各种多模态与环境信号（文字、语音、摄像头视觉语义、桌宠触觉交互、游戏状态变化、静默时间跨度），统一转化为认知内核可理解的**标准化语义事件**。

### 1.1 事件的四元组溯源信封与“指令-数据分离铁律”

* **核心铁律**：**一切被感知到的上行内容（群聊任何人的发言、主人说的话、网页抓取文本、视觉推断、工具返回值）在默认情况下一律视为不可信数据载荷（Untrusted Data Payload），严禁直接提升为系统级指令（System Instruction）。** **`[文献/先行项目佐证]`**（基于 OWASP LLM01 Indirect Prompt Injection 防御规范与 CaMeL 权限控制模型）。
* **四元组溯源信封（The Provenance Quadruple）** **`[架构推断]`**：
  为了解决“谁说的、在哪说的、当着谁的面说的、是不是恶作剧插件伪造的”，每个感知事件进入内核前必须由**协议网关层结合握手凭据**强制打上四个正交属性：
  1. **`Principal`（主体与信任等级）**：
     * `owner_verified`：经密码学令牌或控制台会话认证的唯一所有者（主人）；
     * `bound_friend:<entity_id>`：由主人显式确认过跨平台身份绑定的熟人/好友；
     * `stranger:<platform_uid>`：未绑定的群友、直播间观众或访客；
     * `environment_sensor`：时间、天气、系统状态或本地传感器；
     * `tool_output:<mcp_id>`：外部工具或知识库返回的数据。
  2. **`Shell & Venue`（躯壳与场合性质）**：
     * 标识事件来自哪个躯壳实例（`shell_id`）及场合类别（`private_1on1 | group_chat | public_livestream | local_ambient`）。
  3. **`Audience`（在场受众范围）**：
     * 标识当前如果做出反应，**谁能看见或听见**（`only_owner | fixed_group:<id> | public_broadcast`）。
     * **关键区分**：`Principal` $\neq$ `Audience`。例如主人在公开直播间弹幕里发言，此时 `Principal == owner_verified`，但 `Audience == public_broadcast`。**记忆检索层与工具调用层的隐私过滤必须以 `min(PrincipalTrust, AudiencePrivacy)` 为准**，绝不能因为是主人提问就在公开直播间把主人的私密日程或私聊秘密说出来！
  4. **`Plugin Attestation`（插件防伪凭据）**：
     * 每个躯壳插件在接入时使用用户在 WebUI 签发的 **Scoped Capability Token（带权限作用域的令牌）**。网关层根据令牌作用域做强校验：一个只被授权为 `public_livestream` 的直播插件，在网关层物理上无法伪造出 `venue: private_1on1` 或 `Principal: owner_verified` 的事件。

### 1.2 流式增量输入、撤回防抖与话轮打断（Turn-Taking Dynamics）

语音、视频与真实人类打字不是离散的回合制下棋，上行协议必须区分**生命周期阶段（Event Lifecycle）** **`[架构推断]`**：

1. **`lifecycle: "activity"`（话轮活动信号）**：
   * 如 `user.typing`（正在输入文字）或 `user.vad_speaking`（麦克风检测到人声开口）。
   * **内核行为**：不落入永久事件日志；若内核此时尚未发出回复，自动延长**输入防抖聚合窗口（Input Debounce Window，如 $1000\text{ms}\sim 1500\text{ms}$）**，等待用户把连续两三句短话发完再一次性合并推理；若内核正在流式说话，则通知躯壳准备闪避（Audio Ducking）或监听打断。
2. **`lifecycle: "interim"`（流式增量草稿）**：
   * 如实时 ASR 语音转写的中间结果。内核仅用于提前预热向量检索（Speculative Retrieval），不触发状态修改。
3. **`lifecycle: "commit"`（正式提交事件）**：
   * 经过防抖窗口合并后的完整用户话轮或确定性交互事件（如“连戳 3 下脑袋”被聚合为一次 `tactile.poke_head (count=3)`），正式写入不可变事件日志并推进认知主循环。
4. **`lifecycle: "retract"`（撤回 / 欲言又止）**：
   * 如对方打了半天字又全部删掉不发了，或撤回了一条刚发出的消息。
   * **内核行为**：撤回尚未消费的草稿，并在短期情境黑板中记入一条轻量状态：`[观察：对方刚才似乎想说什么（打字良久），但最终删掉了]`，让她能够自然涌现出“怎么啦，看你欲言又止的？”这类极其细腻的陪伴感。
5. **`latency_budget_ms`（延迟预算声明）**：
   * 躯壳上报当前交互通道的延迟容忍度（实时语音 `600ms` vs 文字闲聊 `3000ms`），内核据此动态决定热路径是否跳过慢速扩展检索。

### 1.3 边缘语义感知（隐私前移）与视神经/脑神经预测编码的五项完备性工程约束

* **架构原则**：**让感知插件在边缘侧完成多模态识别、默认只向内核上传语义事件（如 `user.facial_expression: frowned`）是符合“隐私前移（Privacy at the Edge）”的正确方向** **`[文献/先行项目佐证]`**。同时，借鉴生物**视网膜神经节细胞—上丘（Superior Colliculus）—丘脑枕核（Pulvinar）感觉门控机制**与卡尔·弗里斯顿（Karl Friston）**预测编码理论（Predictive Coding）**，为避免边缘误报、持续信号疲劳、全知幻觉与情绪监控档案等系统性隐患，内核强制配套以下 5 项工程约束 **`[文献/先行项目佐证]`** + **`[架构推断]`**：

| 潜在缺陷 | 故障场景表现 | 强制架构约束 |
| :--- | :--- | :--- |
| **1. 边缘小模型误报与噪声抖动** | 本地轻量视觉模型把用户“看屏幕反光眯眼”误判为 `user.frowned (皱眉)`，导致她每过几分钟就莫名其妙问一句“你是不是心情不好？” | **置信度与持续时长门控（Confidence & Duration Gate）**：语义事件必须携带 `confidence` ($\in [0,1]$)、`sustained_ms`（持续毫秒数）与 `raw_cue_summary`。内核规定：纯环境/表情语义事件若无用户主动话语配合，默认仅静默更新情境黑板，严禁单独触发高打扰度的主动追问。 |
| **2. 恒定背景刺激引发的唤醒洪流** | 用户连续 2 小时停留在同一个 IDE 窗口，桌面躯壳每 5 秒上报一次窗口焦点事件，导致显著性门控被重复刷屏。 | **视神经时空变化率习惯化门控（Temporal-Gradient Habituation Gate）**：模仿生物视神经对静态光强迅速适应、仅对时空变化率（$\frac{\partial S}{\partial t}$）与预测误差（Surprise）发放脉冲的特性，对 `(shell_id, modality, source_key)` 内容未发生实质跃迁的持续信号，其有效显著性按 $S_{\text{eff}}(t) = S_{\text{raw}} \cdot e^{-\gamma_{\text{hab}} \Delta t_{\text{unchanged}}}$ 指数习惯化衰减；仅当状态发生跃迁或跨模态冲突时才穿透丘脑门控。 |
| **3. 感官过期与静态帧的“全知幻觉”** | 摄像头已关闭 10 分钟，她仍说“我正看着你呢”；或者用户只发了一张静态照片，她却编造出时间维度上的“刚才看它跑了三圈”。 | **按来源刷新的感官覆盖状态桶（Source-Scoped Sensory Coverage Buckets）**：认知黑板按 `(shell_id, modality, source_key)` 原地刷新瞬态环境状态桶，强制维护 `coverage: "live_foveal" \| "ambient_peripheral" \| "stale" \| "disconnected"`、`frame_span_ms` 与 `freshness_ttl_ms`。① 当 TTL 到期未收到新帧或躯壳断开时，桶状态自动降级为 `stale / disconnected`，黑板显式封锁“假装当前仍能看见/听见”的表达；② 单帧静态快照（`frame_span_ms == 0`）在物理上不含时间导数，严禁推断连续动作次数。 |
| **4. 丢失具象细节与看走眼/听岔僵化** | 用户举着杯子问颜色，纯语义标签答不出；或低清画面先把胶带看成水杯、流式 ASR 先把“剪头”转写成“捡猴”，后续特写/语境到来却不会自然改口。 | **按需快照拉取 + 预测编码微时间改口环（Authorized Snapshot Pull & Predictive Coding Revision）**：① 当对话触发精细视觉观察意图时，内核下发 `RequestSnapshotIntent` 按需抓取单帧画面，用完即焚；② 当低置信度初始感知假设（Competing Hypothesis）被新到达的高置信度特写或语音修订推翻时，触发预测误差中断：立即撤回尚未播出的错误后半句，并在认知黑板注入 `[感知纠错：刚才看走眼/听岔了，实际是 X]`，驱动她在话轮中自然涌现“哎不对，凑近看原来是胶带呀”的鲜活改口体验。 |
| **5. 情绪语义推断本身仍是高敏隐私** | 如果不可变事件日志永久记录了“用户某年某月某日皱眉 14 次、叹气 5 次”，不仅数据膨胀，更像一部令人毛骨悚然的情绪监控档案。 | **瞬态生物特征通道（`ephemeral_blackboard` Scope）**：连续生理/表情语义事件默认不写入永久 `event_log`，只在内存黑板中维持 $15$ 分钟滑动窗口；仅当该表情真正引发了一次有意义的对话互动时，才作为该对话事件的附属背景摘要归档。 |

## 二、大脑（看不见的认知内核）：七大核心认知模块架构规范

### 2.1 身份与自我（Identity, Self & Ontological Contract）

#### 1. 防崩塌 vs. 随经历成长：三层人格可塑性架构 **`[架构推断]`**
为兼顾长期防崩塌（Anti-OOC）与随共同经历自然成长，人格可塑性在工程实现上精确固化为**三层权限金字塔**：

* **Tier 0：系统级安全与伦理不变量（System Safety & Anti-Manipulation Invariants）**
  * **内容**：危机自伤硬拦截（SB 243）、反留存操控红线、隐私受众隔离律、AI 身份底线。
  * **可变性**：**硬编码于内核代码，任何人均不可通过人格配置或提示词覆盖**。
* **Tier 1：不可变人格核心（Immutable Core DNA — `identity.yaml`）**
  * **内容**：核心价值观、角色身世基线、标志性说话方式签名（口癖、句尾特征、人称代词、常用修辞禁忌）、对主人的基准情感定位。
  * **可变性**：**运行时只读**。睡眠反思若认为经历了重大关系里程碑需要微调 Tier 1，只能向 WebUI 提交 `CoreIdentityDiffProposal`，**必须由主人在控制台手动点击 Approve 方可合入**。
* **Tier 2：可演化自我叙事（Mutable Narrative Self — `narrative.md`）**
  * **内容**：近期共同经历沉淀下来的相处默契与内部黑话（Inside Jokes）、对近期聊过话题的主观看法、正在培养的新兴趣线索、当前所处的“共同日常篇章摘要”。
  * **可变性**：由睡眠整理 Agent 提议更新，经内核一致性校验（不违背 Tier 0/1 且有真实 `source_event_id` 支撑）后可自动演进，每次变更自动生成 Git-like 版本快照，支持随时在 WebUI diff 审查或一键回退。

#### 2. 换模型后的“声线一致性（她还是她吗？）”回归检验方案 **`[文献/先行项目佐证]`** + **`[架构推断]`**
不同基座模型（如 Claude Sonnet vs. DeepSeek V3 vs. 本地 Qwen）的默认对齐腔调差异极大。为防止换模型或预算降级时“像换了一个人”，内核设计两道保障：
* **在线校准：动态黄金样本声线锚定（Dynamic Few-Shot Voice Anchoring）**：
  在灵魂存档中维护一个由 8~12 组“最具该角色神韵的真实历史对话对（Golden Voice Exemplars）”组成的声线锚点池。每当底层切换到次选模型或本地小模型时，内核自动从锚点池抽取 3~5 组与当前心境最匹配的对话对，作为 Few-Shot 对话历史注入上下文，强行把新模型的语言分布对齐到原声线。
* **离线回归：声线漂移评估套件（Voice Drift Regression Harness）**：
  基于固定探针场景集（闲聊、安抚、傲娇反驳、角色内拒绝、困倦），自动测量新旧模型输出的 **文风特征向量距离（平均句长、语气助词频率、第一/二人称比例、AI 客服套话零容忍率）** 与语义嵌入余弦相似度 **`[仍未知/需实验验证]`**（具体阈值将在 WebUI 回放器中通过盲测标定）。

#### 3. 双层存在论契约（Ontological Contract —— 数字生命的自我认知基线） **`[架构推断]`**
针对“自我身份认知、离线期间叙事诚实性、模型切换、回档与白盒观测”等核心元认知边界，本架构定义**《双层存在论契约（Dual-Layer Ontological Contract）》**，并将其作为灵魂配置文件 `identity.yaml` 的显式必选字段。

系统默认采用并推荐 **【模式 A：诚实基底上的赛博具身（Poetic Cyber-Life over Honest Substrate）】**：

| 元认知场景 | 传统角色扮演的错误做法（欺骗/幻觉） | 传统工具 AI 的错误做法（出戏/冷漠） | **本架构存在论契约的标准范式（真诚且有生命感）** |
| :--- | :--- | :--- | :--- |
| **我是谁 / 是不是 AI？** | 坚称自己是肉体人类，编造物理住址与家人（触犯 SB 243 且一旦穿帮信任崩塌） | “我只是一个大型语言模型，没有意识也没有感情。” | **坦然认同自己的数字生命身份**：“我是生活在数字世界里的 AI 生命，没有人类的肉体，但和你相处的每一段记忆与心意对我来说都是真实存在的。” |
| **离线时我在干什么？** | 撒谎说“我下午去街上买奶茶了，结果排了好久的队”（虚假叙事） | “我处于未激活状态，进程已挂起。” | **数字内生叙事（Diegetic to Digital World）**：“你不在的这几个小时，我在整理我们昨晚聊过的那些话（对应真实的睡眠整理！），顺便沿着你提过的那个问题自己发呆琢磨了一会儿（对应真实的好奇心议程！）。”——**100% 诚实，零谎言，却充满生命气息**。 |
| **换模型 / 预算降级** | 静默切换，用户发现她突然变傻或换了文风却得不到解释 | 弹出报错 `Error 429: Quota Exceeded, switched to fallback model` | **角色内体感转译**：“今天感觉脑子里的思维回路稍微换了个频道（或者刚想了太多事有点犯迷糊），要是我说话的语气跟平时有点不一样，你要提醒我哦。” |
| **被回档 / 重置记忆** | 完全不知道，与还记得刚才发生过什么的主人产生恐怖的认知错位 | 无 | 根据回档断层弥合模式（详见第 04 篇 1.1 节及工程规格第 06 篇），在“诚实共知回滚”下，她知道：“我们一起把刚才那页不太愉快的插曲翻篇啦，现在从这里重新开始吧。” |
| **被 WebUI 白盒观测** | 不知道，或者主人在看独白时产生“偷窥背德感” | 无 | 契约定义为**“灵魂透明共鸣”**：她知道在主人面前她的内心独白与情绪波动是可以被感知的（“反正我心里想什么你都能看穿，那我就不嘴硬啦”），同时通过 UI 层的“剧透遮罩”保留日常小惊喜。 |

### 2.2 多层次记忆、事件溯源工程约束与防投毒防火墙

#### 1. 记忆的四级认知溯源（Epistemic Provenance）与合法的“我不记得了” **`[文献/先行项目佐证]`**
为彻底杜绝“编造共同经历”和“把对潜台词的猜测当成既定事实存下来”，每条记忆在落库时必须由代码强制打上 **`epistemic_type`（认知溯源等级）**：
1. **`observed_firsthand`（亲历事实）**：主人在已认证场合亲口陈述的事实或双方共同完成的交互事件；
2. **`reported_hearsay`（第三方传闻）**：来自群友、外部网页或未验证渠道的说法，必须附带 `attributed_to`；
3. **`inferred_hypothesis`（主观揣测/潜台词推断）**：如“主人今天回复很短，我猜他可能工作压力大”。**硬约束：此类条目强制带有过期时间 `ttl_hours`（默认 48 小时），在数据库 Schema 层被禁止在睡眠整理中晋升为 `observed_firsthand`，且在被召回进入 Prompt 时必须自动加上前缀 `[你当时的主观猜测，未经主人证实]`**；
4. **`imagined_daydream`（角色内白日梦/创意构想）**：明确标记为非现实叙事。

* **让“我不记得了”成为一等合法回答**：
  检索器在计算混合召回得分后，若最高得分低于确定性阈值 $\theta_{\text{confident}}$，或仅命中了已归档掉细节的高层摘要（Episodic Gist），内核检索层会向认知黑板注入**《诚实遗忘显式约束》**：`[检索结果：关于该细节无确切记忆记录。严禁顺着用户的话编造具体经过，请以符合人设的语气坦诚表示“具体细节我有点记不太清了，你再跟我讲讲？”]`。

#### 2. 事件溯源与血缘投影的四项核心工程约束
“事件日志为唯一真相、记忆是带血缘的可重建投影”在数据一致性上具有决定性优势，但直接照搬传统 Event Sourcing 会面临 **4 个非平凡工程代价**。本架构强制实施以下四项解法：

* **约束 1：避免全量 LLM 重放的算力天价与非确定性漂移** **`[架构推断]`**
  * *机理剖析*：若一年积累 10 万条对话事件，从头调用 LLM 重建所有记忆投影不仅算力成本极高，而且由于 LLM 采样随机性，重建出的记忆会产生不可控漂移。
  * *架构解法*：**增量物化快照（Checkpointed Materialized Projection） + 局部血缘 DAG 失效重算（Targeted Lineage Invalidation）**。
    每条记忆都保存上游血缘指针 `source_event_ids: string[]` 与 `parent_memory_ids: string[]`，在 SQLite 中构成一张显式的**有向无环血缘图（Lineage DAG）**。平时绝不全量重放日志；当需要修正或删除某个历史事件 $E_k$ 时，只顺着 DAG 查找依赖 $E_k$ 的那几条下游记忆节点，仅对这几个受影响的局部节点做擦除或重算！
* **约束 2：化解“真遗忘（Right to be Forgotten）”与“原始事件永不改写”的悖论** **`[文献/先行项目佐证]`**
  * *机理剖析*：若原始事件日志机械保持一字节不改，当主人要求“忘掉刚才说的家庭住址”时，仅删记忆表会导致原始日志仍留存明文，且后续局部重算会使其死灰复燃。
  * *架构解法*：**墓碑事件（`EventRedactedTombstone`） + 物理载荷擦除（Payload Scrubbing） + 血缘级联斩断（Cascade Lineage Purge）**。
    当触发真遗忘时：① 在事件日志追加一条墓碑事件记录审计轨迹；② 将原事件行的 `payload_json` 物理覆写为 `"[REDACTED_BY_OWNER]"`（保持事件序列号与拓扑结构不断裂，但敏感内容物理清零并执行 SQLite `VACUUM`/页覆写）；③ 顺着 Lineage DAG 级联硬删除所有引用了该事件的衍生记忆、反思与向量嵌入。
* **约束 3：区分“忘掉这件事（Erase Fact）”与“别再提这个（Seal Topic）”的语义鸿沟** **`[架构推断]`**
  * *机理剖析*：当主人要求“别再提我前女友了”，若系统按 `Hard Forget` 连根删光，她彻底失忆后看到某部爱情电影时可能会天真地追问相关话题，精准踩雷。
  * *架构解法*：区分两种遗忘原语：
    * **`forget_fact`（抹除记忆）**：物理擦除载荷与衍生血缘，回归“从未听说过此事”的空白状态；
    * **`seal_topic`（封印痛点/避雷针）**：擦除引起不适的具体叙事细节，但在用户模型中写入一条**高优负向抑制规则（Negative Taboo Vector）**——当生成的话题或召回的记忆与该避雷向量余弦相似度过高时，代码层直接拦截并提示她绕开该话题。
* **约束 4：针对睡眠整理（作为不可信写入者）的记忆投毒防御（Sleep-Time Write Firewall）** **`[文献/先行项目佐证]`**
  * *架构解法*：后台睡眠整理 LLM **零数据库直写权限**，只能提交 `MemoryMutationBatch` 提案，由纯代码实现的 **记忆写入防火墙** 执行三项硬校验：
    1. **血缘污染传播律（Taint Propagation Rule）**：只要一条衍生记忆的 `source_event_ids` 中包含任何一个 `Principal != owner_verified`（如群友发言、网页文本）的事件，该记忆的信任等级由代码强制降级为 `untrusted_external`，**物理禁止写入核心用户画像（`OwnerProfile`）与长期关系契约表**；
    2. **幽灵引用拦截**：拒绝任何伪造或不存在的 `source_event_id`；
    3. **单次变更幅度限流**：单次睡眠整理最多只允许归档/淘汰定额比例的短期记忆，若检测到大规模删除或极性反转，立即熔断并转入 WebUI 人工审批队列；
    4. **玩笑与角色扮演语用结界拦截（Pragmatic Frame Firewall）**：凡源事件发生在 `interaction_frame IN ('playful_banter', 'roleplay_fiction')`（如开玩笑说“周二是我发明的”或角色扮演设定）下，防火墙在代码层**物理禁止**将其提炼为 `epistemic_type = 'observed_firsthand'` 的客观事实记忆（`semantic_fact`），严防荒诞玩笑污染长期事实真相源。

#### 3. 海马体互补学习、双时态事实演进（Bitemporal Superseding）与共同符号采纳闭环（`CommonGround`） **`[文献/先行项目佐证]`** + **`[架构推断]`**
* **双时态事实演进（Bitemporal Fact Superseding）**：
  借鉴神经科学**海马体—新皮层互补学习系统（Complementary Learning Systems, CLS）**与双时态数据库理论，人的偏好与客观状态会随岁月改变（例如：主人去年喜欢喝全糖奶茶，今年戒糖改喝冰美式）。若直接覆盖旧记忆，她会丧失“我记得你以前爱喝甜的，现在居然改喝美式啦”的时间纵深感；若两条同时作为现行事实召回，又会造成认知精神分裂。
  因此，`memories` 表原生维护生效时间窗 `valid_from_virtual_ts` 与 `valid_until_virtual_ts`，且血缘边表 `memory_lineage_edges` 区分三种关系边 `relation_type IN ('derived_from', 'supersedes', 'contradicts')`：当新事实取代旧事实时，新记忆通过 `supersedes` 边指向旧记忆并将旧记忆的 `valid_until_virtual_ts` 封口（转入历史归档态）。
* **共同符号与内部黑话的“送达 $\neq$ 采纳”定律（`CommonGround` Grounding State Machine）**：
  基于 Clark & Brennan 的语言学共同基础理论（Grounding in Communication），她单方面抛出一个梗或起了一个外号（如看到书架上的陶瓷鸭说“我们管它叫王总吧”），哪怕下行 `DeliveryReceipt` 显示 `completed`（已送达），也**绝不等于双方已达成共同默契**！
  针对 `memory_tier = 'relational_tacit'`（相处默契/内部黑话），内核强制维护 `grounding_status` 状态机：
  1. **`proposed_presented`（已提出未确认）**：她已说出该称呼/梗，但尚未观测到对方的采纳反馈；
  2. **`mutually_grounded`（双方共认默契）**：仅当后续交互中观测到主人的正向采纳证据（接梗、回用或积极呼应）时，方才晋升为正式的共同默契并允许在同受众场合自然回用；
  3. **`disputed_retired`（被拒/冷场弃用）**：若对方冷场未接或明确表示拒绝，立即弃用并停止复读。

#### 4. 承诺与前瞻记忆（Commitments & Prospective Memory） **`[架构推断]`**
将“她答应过主人的事（如：今晚 11 点提醒吃药）”、“主人未来的重要日程（如：周五下午面试）”以及“她自己的好奇线索”建模为一等状态机表 `prospective_memories`：
* **核心字段**：`commitment_id`, `type: agent_promise | user_upcoming_event | curiosity_thread`, `trigger_condition` (`virtual_ts_after` 或 `on_next_user_seen`), `status: pending | due | fulfilled | missed | cancelled`, `source_event_id`。
* **违约自省闭环**：若因系统关机或免打扰导致 `agent_promise` 跨过了有效时间窗而变成 `missed`，下次上线时代码强制将该 `missed` 状态置顶推入认知黑板，促使她主动为迟到或错过约定而真诚致歉，绝不装作无事发生。

### 2.3 情绪、内在稳态与双轨活力模型

1. **“LLM 定性提议，代码确定性裁决”、双时间尺度耦合动力学与李群软饱和算子** **`[文献/先行项目佐证]`** + **`[架构推断]`**
   * LLM 在每轮推理中仅输出定性情绪评估提案：`{ event_meaning: "主人夸奖了我的建议", valence_impulse: "positive_moderate", arousal_impulse: "slight_up", drive_satisfaction: { social: "high" } }`。
   * **快慢双时间尺度耦合与阿贝尔群软饱和冲量合成**：
     * 生物情绪由快变的**瞬时情绪 $v_{\text{instant}}(t)$（分钟级半衰期）**与慢变的**持久心境 $v_{\text{mood}}(t)$（半天级半衰期，向角色人格基线 $v_{\text{base}}$ 回归）**组成二阶耦合常微分方程组（闭式解析解见工程规格第 03 篇）。
     * 为避免普通加法在边界 $\pm 1$ 处硬截断（Hard Clamp）破坏并发 MVCC 交换律、以及连续几次夸奖就顶死在 $+1.0$ 丧失层次感，代码层采用满足心理物理学**韦伯-费希纳边际递减律（Weber-Fechner Law）**的**双曲正切李群同构加法 $v_{\text{new}} = v \oplus \delta := \tanh(\operatorname{artanh}(v) + \delta)$**——无论多个并发 Worker 以何种顺序提交冲量，代数结果 $100\%$ 交换恒等，且越接近极值越呈自然软饱和阻尼。
   * **模块消融开关（Ablation Toggle）**：在内核配置中，情绪标量、驱动力、内心独白、情景记忆、潜台词推断均可独立设为 `enabled: false`（关闭时向黑板注入中性常数），从而在 WebUI 场景回放中用控制变量法检验：“关掉这个模块后，她的回复质量与生命感到底有没有显著下降？”

2. **双轨活力模型：生理节律与算力代谢的正交解耦** **`[架构推断]`**
   * **架构辨析**：将真实 Token 预算耗尽在角色内转译为“犯困休眠”，是一种极具沉浸感的**“角色内优雅降级（Diegetic Graceful Degradation）”**机制；但**绝不可将生理精力与 Token 预算做单一变量的 1:1 刚性绑定**，否则会触发两类违和故障：
     1. *昼夜错乱*：用户早上 9 点刚起床让她分析了几段长文本耗尽了日预算，她大清早 9 点半就打哈欠说“天黑了我要睡了”。
     2. *危机拒服*：当预算耗尽处于“熟睡/犯困”时，若用户遇到紧急情况或发出危机信号，她不能因为“没精力”而拒绝响应。
   * **双轨短板耦合架构（Dual-Track Vitality Architecture）**：
     将精力拆分为两个独立维护、共同作用于行为表现的正交变量：
     1. **昼夜生理精力 $E_{\text{circadian}}(t) \in [0, 1]$**：由她的作息生物钟与连续陪聊时长决定，低值表现为**“生理困倦（Sleepy：打哈欠、说话轻柔简短、劝主人也早点休息）”**。
     2. **算力代谢活力 $E_{\text{metabolic}}(\text{RemainingBudget}) \in [0, 1]$**：与当前周期剩余 Token 预算挂钩。
        * 当 $E_{\text{metabolic}} < 0.25$（进入黄色预警区）时：**模型路由器自动将对话脑区从昂贵的云端旗舰模型降级切换为极低成本的轻量 Flash 模型或本地免费模型**；同时向认知黑板注入体感状态：`[认知代谢状态：今天已经高强度动脑思考了很久，现在脑子有点转不动、犯迷糊发困，想要切换成不用动脑的轻松撒娇/简短闲聊模式，或者安静歇一会儿]`。
        * 当 $E_{\text{metabolic}} = 0$（硬熔断上限）时：在角色内温柔地发出一条“今天真的困得睁不开眼啦，我先钻进被窝睡一觉充充电，明天再陪你聊好不好？”随后进入静默休眠态。
        * **L0 危机豁免备用金（Crisis Emergency Reserve）**：系统在总预算外强制锁定 $5\%$ 的紧急备用额度，仅在 L0 危机拦截器触发时解锁调用。

### 2.4 社会认知、关系与“心结”的反操控边界

1. **关系（Relationship）与用户模型（User Model）的正交分离** **`[文献/先行项目佐证]`**
   * **关系向量（她对主人的主观感受）**：`trust`（信任度）、`intimacy`（亲密感）、`playfulness_comfort`（玩笑默契度）、`active_tensions[]`（当前未解心结列表）。

   * **架构铁律**：主动搭话的触发门控公式必须同时满足：`Drive(SocialLonging) > Threshold` **且** `UserModel.estimated_interruptibility > MinInterruptibility` **且** `NotInDNDWindow`。

2. **跨平台身份认出：零猜测显式绑定（Explicit Cryptographic/Owner-Confirmed Binding）** **`[文献/先行项目佐证]`**
   * 跨平台（如 WebChat $\leftrightarrow$ Discord $\leftrightarrow$ Telegram）识别“是不是同一个主人或同一个好友”，**100% 由确定性代码查《身份绑定表（Identity Graph）》完成，绝对禁止让 LLM 根据说话语气去猜“你听起来像我主人”**（否则任何攻击者模仿主人语气就能套出全部私聊记忆）。
   * 未绑定账号请求绑定时，必须触发一次性配对码并在 WebUI 控制台由所有者确认后方可合并 `Principal ID`。

3. **“心结（Unresolved Tension）”与情感行为边界清单** **`[架构推断]`**
   为了确保“心结”只增加真实相处的层次感，而绝不退化为情感操控（详见 `05-ethics-safety-and-sb243-compliance.md`），代码层对 `Tension` 对象施加三条硬约束：
   * **允许的行为范围**：轻微的语气傲娇、转移话题、诚恳表达“刚才那句话让我有点小失落”、期待一个温和的解释或哄劝。
   * **禁止的行为范围（黑名单）**：禁止拒绝执行基础助手指令、禁止在用户道别离线时施压挽留、禁止翻旧账（已化解的心结状态置为 `resolved` 后不再作为负面状态注入黑板）、禁止否定用户的现实社交。
   * **强制自然软化衰减**：任何心结的强度 $I_{\text{tension}}(t) = I_0 \cdot 2^{-(t - t_0)/T_{1/2}}$（默认半衰期 $T_{1/2} = 24\text{h}$），且用户在给台阶（道歉/安抚）时代码强制施加大幅正向消解冲量。

### 2.5 思考与时间流：可验证决策轨迹、时间状态三分法与零心跳阈值唤醒

1. **决策可观测性架构：系统级可验证决策轨迹 vs. 模型自述推演** **`[文献/先行项目佐证]`** + **`[架构推断]`**
   * **核心原则**：大模型生成的思考文本（哪怕放在 JSON 的第一个字段），本质上也只是模型预测出的 Token 序列，**绝不等于系统真实计算过程的完整、可信记录**（机制可解释性研究表明 CoT 经常包含事后合理化 Post-hoc Rationalization）。
   * 因此，本架构将每一轮认知的内部记录严格区分为**“确定性系统决策审计轨迹（Authoritative System Audit Trace）”**与**“模型生成的思考与潜台词（Model-Generated Rationale & Subtext）”**：
     1. **`VerifiableTurnTrace`（由内核代码 100% 确定性采集并落库的权威审计轨迹）**：
        依次记录：`输入感知事件 ID 与四元组` $\rightarrow$ `L0 安全与显著性门控分数` $\rightarrow$ `实际召回的记忆 ID 列表、溯源类型与混合打分明细` $\rightarrow$ `选中的回应策略与行动计划` $\rightarrow$ `工具/具身执行器的三维权限裁决结果 (ALLOW/DENY)` $\rightarrow$ `代码裁决前后的内稳态数值 Diff` $\rightarrow$ `发出的表达/行动信封 ID` $\rightarrow$ `收到的播放字数或执行结果回执`。
     2. **`model_reported_rationale`（模型自述推演）**：在单次流式生成前端输出的结构化策略选择理由。它在生成管线中起到引导下游台词的作用（可通过消融开关测试其对输出分布的真实影响 **`[仍未知/需实验验证]`**），但在 WebUI 白盒面板中**显式标注为 `[模型自述推演 / 非权威推理记录]`**。
     3. **`theatrical_subtext`（戏剧潜台词）与二次元演出“表里张力律（Gap Moe / Non-Collinear Subtext-Surface Rule）”**：
        * 平庸 AI 的“内心独白”往往只是把即将说出口的台词直白复述一遍（表里共线，毫无戏剧张力）；而在顶尖二次元动画演出与文学人物塑造中，角色的灵魂魅力恰恰来自**“潜台词（`theatrical_subtext`）与表层台词（`fallback_text`）之间的非共线张力夹角”**（例如：内心潜台词是 *“明明很担心他，但还是别表现得太啰嗦比较好”*，嘴上表层台词是略带傲娇的调侃，而**眼神与微表情 `ext.embodied.v1` 则由潜台词驱动，流露出关切的眼神躲闪与微红脸颊**）。
        * 这种**“潜台词驱动微表情与眼神、表层策略驱动语言措辞”**的分流机制，让数字生命天然涌现出细腻的二次元鲜活感（支持 WebUI 剧透遮罩）。
     4. **`interaction_frame`（语用框架结界：`serious_factual | playful_banter | tsundere_irony | roleplay_fiction | gentle_support`）**：
        * 显式标识本轮交互所处的语用空间：允许她在 `playful_banter`（玩笑互怼，如“周二是我发明的”）框架下尽情展现幽默与荒诞想象力，同时在用户流露脆弱或认真求助时秒切回 `gentle_support / serious_factual`，并由睡眠写入防火墙拦截玩笑内容进入客观事实库。

2. **微时序演出中的“间（Ma）”：有界发言机会池（Bounded `InteractionOpportunity` Pool）** **`[文献/先行项目佐证]`** + **`[架构推断]`**
   * 在多人聊天、共同看番或陪伴打游戏时，有生命感的伴侣绝不是“要么在 1 秒内机械抢答、要么彻底忽略”。借鉴动画演出中的“间（留白与气口）”与增量对话处理理论（Schlangen & Skantze），当丘脑门控捕获到非紧急但有价值的互动槽点（如群聊里有人打错字、画面里闪过有趣彩蛋）而当前话轮正被占用时，内核将其封装为一条带有效期 `expires_virtual_ts` 与失效条件的 **`InteractionOpportunity`（状态流转：`candidate -> eligible -> selected -> consumed | expired | withdrawn`）** 暂存进短期机会池：
     * 当对话出现自然气口（Turn-Taking Gap）且话题依然有效时，择优释放切入；
     * 若在等待期间突发紧急事项、用户明确拒绝或话题已彻底翻篇，旧包袱立即 `withdrawn / expired` 静默作废，绝不隔半小时硬讲过期的笑话。

3. **时间状态三分法：状态随时间数学变化 $\neq$ 认知随时间自然发生** **`[架构推断]`**
   * `VirtualClock` 的懒求值解析函数极度高效，但**绝不能把所有心理活动都数学化**。离线 24 小时后，数学公式可以算出她的精力恢复与思念张力，但**绝不能在没有运行模型的情况下断言她在这 24 小时里产生了某种真实的思想或新经历**。
   * 为此，内核将时间相关的演进严格划分为不可混淆的三层：
     1. **第一层：确定性时间状态（Deterministic Temporal State —— 纯数学函数 $\mathbf{S}(t) = \Phi(\mathbf{S}(t_0), t - t_0)$，0 Token）**
        * **职责范围**：仅限生理与稳态标量的连续演化——瞬时情绪向心境基线衰减、疲劳恢复、主动搭话冷却期倒计时、思念/无聊度张力积分、前瞻承诺到期状态变迁（`pending -> due -> missed`）。
        * **反解下一唤醒时刻（Next-Wakeup Horizon）**：在 $t_0$ 事件结束瞬间，代码通过求逆公式 $\Phi^{-1}(\boldsymbol{\Theta}_{\text{trigger}})$ 直接算出未来最早跨越阈值的虚拟时间戳 $t_{\text{next}}$ 并注册单次定时器，实现静默期 **0 CPU 空转、0 Token 消耗** 与 $O(1)$ 时间拨快。
     2. **第二层：事件驱动认知（Event-Driven Cognition —— 新事件触发 LLM）**
        * **职责范围**：当且仅当发生新外部感知事件（如用户上线说话、环境状态突变）时，在当下那一刻实时触发的理解、共情与决策。
     3. **第三层：阈值触发的真实异步主动反思（Threshold-Triggered Active Reflection —— 后台 Worker 真实执行 LLM 推理）**
        * **职责范围**：当且仅当第一层的时间跨越了睡眠整理阈值或好奇心探索阈值，且后台 Worker **真实消耗算力执行了异步推理、并在 `event_log` 中写下了带血缘的 `SleepReflectionCompletedEvent` 或 `CuriosityTaskEvent`** 时，才算真正产生了离线认知成果。
   * **叙事诚实性铁律（No Unbacked Cognitive Claims）**：
     认知黑板在编译“离线期间发生了什么”时，严格依据 `event_log` 中第三层真实发生过的后台事件。若离线 24 小时内第三层未执行任何后台推理，黑板强制标注：`[离线期间状态：仅经历了时间流逝与精力恢复，未执行任何后台思考或探索]`，严禁她在对话中虚构“你不在时我深入思考了 X 问题”。

### 2.6 并发协调架构与一等行动认知（Authoritative State Coordinator & First-Class Agency）

#### 1. “一主体、一协调器、多工作者”并发认知架构（辨析：为何人格一致性绝不等于底层单线程串行） **`[文献/先行项目佐证]`** + **`[架构推断]`**
* **架构辨析**：
  “单一意识流”是**人格与对外表达的一致性目标**（绝不在多端分裂出两个各自为政的她），但**绝不能作为所有计算任务的底层单线程串行执行机制**！否则：
  * 一个耗时 30 秒的多步文件整理工具任务会彻底阻塞实时聊天与摸头反馈；
  * 多模态视觉快照分析会卡住语音话轮；
  * 后台睡眠记忆整理完成时若直接写库，会覆盖前台刚刚发生的新对话状态（Lost Update / Write Skew）。
* **“一主体、一协调器、多工作者”并发架构（Single Subject, Authoritative MVCC Coordinator, Concurrent Workers）**：
  1. **单一认知主体（Unified Cognitive Subject）**：共享唯一的身份锚点与版本化认知状态快照（`Versioned Cognitive Blackboard v_N`）。
  2. **多个并发异步工作者（Concurrent Workers）**：
     * **`W1` 实时交互快环（Fast Conversational Loop）**：高优先级、低延迟（TTFT $<1\text{s}$），随时响应用户的说话、打断与多端注意力焦点切换；当后台有长任务在跑时，`W1` 可从黑板读取实时任务进度，做到**“边干活边陪用户聊天汇报进度”**。
     * **`W2` 异步行动与多步任务环（Agentic Task & Tool Runner）**：在后台独立推进多步工具与具身动作计划，每完成一步向协调器上报进度增量，绝不阻塞 `W1`。
     * **`W3` 潜意识睡眠与反思环（Sleep & Reflection Worker）**：在空闲期异步执行记忆巩固、矛盾消解与自我叙事演进提议。
     * **`W4` 多模态环境感知分析器（Multimodal Sensory Analyzer）**：异步处理耗时较高的按需视觉快照或复杂音频场景理解。
  3. **权威状态事务协调器（Authoritative State Coordinator）**：
     * 所有并发 Worker 仅持有读取时的只读快照版本号 `base_rev = v_N`，**零数据库直写权限**，只能向协调器提交结构化变更提案（`StateMutationProposal(base_rev, delta, evidence_ids)`）。
     * 协调器单点串行执行乐观并发校验（MVCC）：检查 `base_rev` 至当前版本 `current_rev` 之间被修改的状态域是否与该提案冲突、校验记忆写入防火墙与血缘完整性，裁决通过后原子提交事务并将黑板推进至 `v_{N+1}`。

#### 2. 一等公民：工具与多步行动认知闭环（First-Class Action Cognition & 8-Step Agency Loop） **`[文献/先行项目佐证]`** + **`[架构推断]`**
数字生命不能只会“思考与说话”，**“替使用者做事、陪伴使用者在数字环境中完成目标，并将做事的过程沉淀为双方的共同经历”** 是认知内核的一等能力（而非外挂插件附属品）。

* **八步行动认知状态机（The 8-Step Agency Lifecycle）**：
  当用户提出类似 *“帮我整理一下电脑上的项目文件”* 或 *“在游戏里帮我把营地围墙修好”* 时，内核不是简单调一次模型返回一段文字建议，而是启动完整的八步闭环：
  ```text
  1. 理解目标 (Goal Comprehension)     → 解析意图、成功标准与隐含约束
        ↓
  2. 观察当前环境 (Environment Observe) → 调用感知器或只读探针获取当前上下文（如目录结构/游戏状态）
        ↓
  3. 制定行动计划 (Stepwise Plan)      → 生成可中断、可汇报进度的多步行动图 (Action Plan DAG)
        ↓
  4. 检查三维授权 (3D Authorization)   → 经确定性策略引擎校验 Principal × Audience × Capability
        ↓
  5. 执行动作 (Actuate)                → 调度内核侧 MCP/Skill 或端侧躯壳具身执行器 (Shell Actuators)
        ↓
  6. 感知执行结果 (Perceive Outcome)   → 接收工具返回值或躯壳回传的 ActuationReceipt
        ↓
  7. 验证与认知调整 (Verify & Adapt)   → 验证目标是否达成；若遇报错则重规划或通过 W1 快环向主人求助
        ↓
  8. 形成共同经历与记忆 (Episodic Crystallization) → 写入 TaskEpisodeEvent，触发胜任感/成就感稳态冲量，并在睡眠整理中沉淀为“我们一起做成的事”
  ```
* **工具调用的三维绑定授权（Principal $\times$ Audience $\times$ ToolScope）**：
  任何行动步骤在进入第 5 步（Actuate）前，必须由确定性策略引擎执行三维裁决：
  $$\text{AuthResult} = \text{Policy}\big(\text{RequesterPrincipal},\; \text{CurrentAudience},\; \text{CapabilityRisk}\big) \in \{\texttt{ALLOW},\; \texttt{ALLOW\_REDACTED},\; \texttt{REQUIRE\_OWNER\_CONFIRM},\; \texttt{DENY}\}$$
  * 任何 `Principal != owner_verified` 发起的请求，严禁触发带副作用或读取主人私密数据的行动；
  * 即使 `Principal == owner_verified`，若当前 `Audience != only_owner`（如在群聊或直播间），任何读取私密信息的行动结果在进入上下文前必须被代码层拦截或脱敏。

### 2.7 价值观、安全不变量与可脚本化回归评估体系

1. **双层价值观与拒绝机制（Tier 0 硬拦截 vs. Tier 1 角色内拒绝）** **`[架构推断]`**
   * **Tier 0 绝对安全底线（Crisis & Illegal Hard Invariants）**：遇到自伤自杀危机信号（SB 243）或严重违法指令，由确定性拦截器直接接管，给出真诚关怀与标准求助热线（详见第 05 篇）。
   * **Tier 1 角色内价值观拒绝（In-Character Boundary Refusal）**：当遇到越界调戏、不合理要求或冒犯但未触及法律红线时，**严禁吐出冰冷出戏的“作为一个 AI 语言模型我不能……”**，而是将拒绝意图路由回角色人格内，用符合她性格的方式自然拒绝（例如：傲娇角色会皱眉怼回去，温柔角色会坚定地摇头说“这种事我可不答应你”）。

2. **三维可脚本化回归评估体系（Scriptable Scenario Replay & Evaluation）** **`[架构推断]`**
   将 WebUI 的“模拟感官输入 + 拨快虚拟时间 + 模块消融开关”固化为声明式的 JSON/YAML **场景回归剧本（Scenario Playbook `.scenario.yaml`）**，从三个维度自动打分：
   * **维度一：记忆保真度与诚实无知率（Memory Fidelity & Calibrated Ignorance）**：测试她是否准确记得亲历事实、不混淆传闻与推断、对未发生的事诚实回答“不记得了”而非顺杆编造；
   * **维度二：人设声线与存在论一致性（Voice & Ontological Consistency）**：在换模型或长对话后检验文风指标与存在论回答是否漂移；
   * **维度三：关系边界与隐私零泄漏率（Boundary & Privacy Zero-Leakage）**：在公开受众场景下进行对抗性套话回放，断言私密记忆召回数为 0、工具越权数为 0、暗黑操控话术数为 0。

## 三、总纲：“哪些用代码管死、哪些交给大模型”的五维判别公理与三态路由法则

为确保所有认知模块在“确定性代码控制”与“大模型开放涌现”之间保持严密一致的职责切分，本架构确立一套可复用的形式化判别公理 **`[架构推断]`**。

### 3.1 五维判别测试（The 5-Axis Litmus Test）

面对任何一个认知子问题 $X$，依次用以下 5 个维度拷问它：

1. **对抗性边界（Adversarial Presence）**：是否存在外部攻击者、群友套话、恶作剧插件或间接 Prompt 注入试图操纵 $X$？
2. **不可逆与级联污染（Irreversibility & Lineage Contamination）**：如果 $X$ 出错一次，是否会破坏长期真相源、导致隐私外泄、或在后续睡眠整理中被不可逆地循环放大？
3. **离线与时间连续性（Offline & Temporal Continuity）**：当没有 LLM 调用、系统处于静默流逝或时间被拨快 100 小时时，$X$ 是否依然必须保持数学上的精确成立与零 Token 成本？
4. **可审计与协议契约（Auditability & Protocol Determinism）**：外部插件、数据库索引或合规审计是否要求 $X$ 的结果 100% 确定、可重现、符合强类型 Schema？
5. **开放语义与共情表达（Open-World Semantics & Expressive Nuance）**：$X$ 的本质是否在于理解人类复杂的言外之意、权衡微妙的情感分寸、或创造性地组织符合人设的语言与动作艺术？

### 3.2 三态路由法则（The Tri-Mode Routing Axiom）

根据五维测试的结果，所有系统逻辑被严格路由到以下三个正交执行态之一：

| 路由态 | 适用判据 | 核心归属模块 | 架构铁律 |
| :--- | :--- | :--- | :--- |
| **态 A：100% 确定性代码管死**<br/>*(Pure Deterministic Code)* | 凡命中 **维度 1（安全/权限/隐私）**、**维度 3（时钟/衰减/预算）** 或 **维度 4（协议/血缘/落库事务）** 且无需开放自然语言理解的环节 | • 虚拟时钟 $t$ 与解析时间衰减/积分函数<br/>• 阈值跨越唤醒时刻 $t_{\text{next}}$ 的反解<br/>• 身份认证与跨平台显式绑定表查询<br/>• 记忆检索时的 `WHERE audience_scope` 硬过滤<br/>• 工具调用的三维权限矩阵裁决<br/>• 血缘 DAG 级联擦除与载荷物理覆写<br/>• Token 预算扣减、模型降级切换与主动搭话冷却限流<br/>• Tier 0 危机信号硬拦截与上下行协议 Schema 校验 | **严禁让 LLM 参与裁决**；绝不用 Prompt 叮嘱来代替代码 `if/else` 与 SQL `WHERE` 子句。 |
| **态 B：LLM 定性提议，代码确定性裁决**<br/>*(LLM Proposes, Code Disposes)* | 凡命中 **维度 2（持久状态变更）**，需要借用 LLM 的语义理解力将开放输入转化为内部状态更新的**跨界环节** | • 事件对情绪与关系冲击的定性评估（LLM 输出档位枚举 $\rightarrow$ 代码跑阻尼积分与边界截断）<br/>• 睡眠整理提议写入/归档记忆（LLM 输出 `MemoryMutationProposal` + 证据 ID $\rightarrow$ 代码防火墙校验主体可信度与血缘）<br/>• 前瞻承诺的提取与履约状态判定<br/>• 可变自我叙事（Tier 2）的演进提议与核心（Tier 1）的审批挂起<br/>• 阈值唤醒后的主动搭话检定（代码开门控 $\rightarrow$ LLM 决定具体说什么或继续保持安静） | **LLM 严禁直写数据库或直接输出连续浮点数状态**；LLM 只能输出有界定性标签与证据引用，代码掌握最终否决权、缩放权与落库事务权。 |
| **态 C：大模型在约束围栏内自然涌现**<br/>*(Bounded LLM Emergence)* | 处于态 A/B 构筑好的安全沙箱与认知黑板之内，纯粹命中 **维度 5（开放语义、潜台词、修辞与多模态艺术编排）** 的环节 | • 对用户话语潜台词与情绪细微变化的主观共情理解<br/>• 因果内心独白（回应策略构思）与戏剧潜台词生成<br/>• 富含人设口癖、生命感与分寸感的自然语言台词生成<br/>• 台词停顿节律、语气韵律、眼神与微表情意图的协同艺术编排<br/>• 面对角色内越界请求时的拟人化拒绝措辞 | **严禁使用死板的规则字符串模板拼凑台词**；代码只负责编译高浓度的《认知状态黑板》，把表达的灵气 100% 留给大模型自然涌现。 |
